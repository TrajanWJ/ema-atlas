# EMA v1.1 Execution Roadmap

> Ordered build plan from "many apps don't work, CLI barely functions"
> to "daemon independent, backbone on the t3code spine, GUI legible,
> CLI is a real client." Session-sized phases. Each phase ships
> independently.

## Ordering principle

Two axes of work run in parallel:

- **Hygiene axis** — legibility fixes that don't touch architecture.
  Session-sized. Each one independently shippable. No dependency on
  sub-project A. Their purpose is to stop the system from lying about
  what's broken and to make further work diagnosable.
- **Architecture axis** — sub-project A (independent daemon + backbone),
  then sub-project C (vApp contract + chat port), then D+ (follow-up
  domain migrations). Big, phased, sequential.

The two axes meet at phase A5 (client cutover), where hygiene fixes to
`api.ts` and the renderer stores get migrated onto the Effect RPC
client. After that, the axes rejoin into a single track.

## Legend

- 🪶 **H** — hygiene (can ship alone, no deps).
- 🏗 **A** — sub-project A phase.
- 🧩 **C** — sub-project C phase.
- 📦 **D+** — follow-up migration passes.
- 🛑 **gate** — a user decision blocks the next step.

## Session 1 — GUI hygiene 🪶H

Make the system stop lying. No architecture changes. Parallelizable with
CLI hygiene (session 2) by a different agent if desired.

1. Rewrite `apps/renderer/src/lib/api.ts` error handling to produce
   structured `{ status, code, message, body }` responses and propagate
   real context. No `"unknown"` string anywhere.
2. Add `apps/renderer/src/lib/capture-error.ts` — normalizes and logs
   unknown errors. Export helper for store catch blocks.
3. Codemod-or-hand: replace `.catch(() => {})` / `.catch(() => [])` idioms
   across `apps/renderer/src/**/*store*.ts` with `.catch(captureError)`
   that stores a legible error on the store.
4. Add `"typecheck": "tsc -b"` (or workspace equivalent) to root
   `package.json`. Run it. Fix the first wave of errors it surfaces in
   `shared/` and renderer edge files.
5. Add `/api/backend/routes` introspection endpoint in services;
   renderer calls it on startup to build a set of available routes.
6. Add `<NotWiredYet route={...} reason={...} />` placeholder component.
   Route it for every `KEEP-BUT-QUARANTINE` / `DEFER` app in the triage
   ledger.
7. Remove `UNWIRE-SYSTEM-CONCEPT` routes from `App.tsx` switch; strip them
   from the launchpad. (They still exist in `services/` — they simply
   stop pretending to be vApps.)
8. Implement `MERGE-INTO` redirects in `apps/renderer/src/lib/router.ts`.
9. Wrap `openApp()` in `App.tsx` with try/catch + captureError; no more
   silent dead clicks.
10. Sweep unrouted `apps/renderer/src/components/**` directories to
    `apps/renderer/src/components/_attic/`.

**Ships when:** every renderer route resolves to either a real component
with real errors surfaced, or a NotWiredYet card that explains status.
Zero `"unknown"` strings in the codebase. `pnpm typecheck` passes from
the root.

## Session 2 — CLI hygiene 🪶H

Parallelizable with session 1 (different subtree).

1. Retire `bin/ema` (Python). Move to `IGNORE_OLD_TAURI_BUILD/bin/ema` or
   delete outright.
2. Install TS CLI as canonical `ema` entry point on PATH. Document how.
3. Standardize output envelope: add `cli/src/lib/io.ts` exposing
   `print`, `printJson`, `fail`. All commands go through it.
4. Add `--json` / `--quiet` flags to every command family.
5. Detect "daemon missing" case and print actionable error message with
   instructions. No more silent connection-refused.
6. Mirror `captureError` helper from session 1 for parity.
7. Write `cli/README.md` that describes only what is real today. Archive
   anything aspirational.

**Ships when:** `ema health` works or prints an actionable error. All
commands accept `--json`. There is exactly one `ema` binary on PATH.

## Sessions 4–9 — Sub-project A phases 🏗A

Phases A1–A6 from the spec. Each is its own session or sub-session.

### Session 4 — A1 contracts + Effect runtime

Add Effect deps. Create contracts package. No behavior change. Tests
pass.

### Session 5 — A2 persistence foundation

Add event log + projection tables + migration runner. Tests pass.

### Session 6 — A3 daemon lifecycle + CLI + auth

`ema daemon start|stop|status|logs`. Electron flips from subprocess
owner to client. Auth non-optional. Coexistence with old routes.

🛑 **gate:** first user test drive. "Can I close Electron and have the
daemon still run? Can I reopen Electron and reconnect?" Answer must be
yes before proceeding.

### Session 7 — A4 loop reshape

Loop domain moves onto decider/projector/reactor. Dual-write phase, then
cutover. 143 tests pass against projections.

### Session 8 — A5 client cutover

Renderer + CLI migrate from Phoenix-wire-over-ws + HTTP-via-api.ts to
Effect RPC. Phoenix dep removed. Old ws reimpl deleted.

🛑 **gate:** second user test drive. "Do the KEEP-AND-WIRE apps from the
triage ledger still work end to end?"

### Session 9 — A6 cleanup + migration backfill

Drop `loop_*` tables. Retire Fastify host. Retire
`EMA_API_TOKEN` optional path. Rewrite docs. Tag release.

**Ships when:** sub-project A acceptance criteria §6 all hold.

## Sessions 10+ — Post-A parallel tracks

Multiple tracks can start once A lands. They are listed in rough priority.

### Track GUI-wire — wire the KEEP-AND-WIRE renderer apps 🪶H

One session per app. Fix contract drift against the new RPC surface,
validate end-to-end in the UI. Priority order:

1. `desk` — default home, highest visibility.
2. `brain-dump` — capture funnel, feeds everything.
3. `tasks` — core productivity surface.
4. `focus` — self-contained, easy end-to-end win.
5. `goals` — backend exists already.
6. `pipes` — real backend.
7. `settings` — core.
8. `wiki` — read-only works today, fix write/nav.
9. `journal` — small new backend needed.
10. `one-of-{operator-chat,agent-chat}` — after user picks which.

### Track CLI-surface — expand CLI command families 📦D+

Add CLI command families mirroring canon objects. Depends on shared
object model decision. Depends on A5 (RPC client).

### Track C — vApp contract + chat port 🧩C

Separate sub-project. Brainstorm starts in parallel with session 4 (A1)
now that A is locked. Implementation starts after A ships. Delivers:

- vApp manifest format
- vApp loader in `apps/electron/main.ts`
- t3code chat ported as the reference vApp
- design token consumption
- launchpad registration

### Track D+ — domain migration passes 📦D+

One pass per non-loop domain: spaces, goals, calendar, chronicle,
journal, review, etc. Each migrates to the event-sourced spine. No hard
deadline; ordered by which unlocks the most renderer value.

### Track shell — HQ becomes the shell 🪶H

Per triage ledger open question 2. Non-urgent but architectural. Moves
HQApp from "a vApp tile" to "the shell that hosts vApps." Depends on
the vApp contract from track C.

## Success criteria for v1.1

v1.1 is done when all of the following hold:

1. Zero `"unknown"` error strings reachable from the renderer.
2. `pnpm typecheck` passes from the root.
3. `ema daemon start|stop|status|logs` works.
4. Electron is a client, not a process parent.
5. Phoenix is no longer a renderer dependency.
6. At least the top 6 apps on the track GUI-wire list work end to end.
7. Triage ledger dispositions are all implemented (wired, quarantined,
   unwired, merged, or deferred — nothing still pretending to work).
8. CLI has one binary, a JSON output mode, and daemon lifecycle
   commands.
9. Loop domain runs on event-sourced spine; 143 tests pass.
10. Docs (`OPERATING-REALITY.md`, `GROUND-TRUTH.md`,
    `backend/README.md`) describe the current architecture accurately.

Anything beyond this is v1.2+. Resist the urge.

## Out of scope for v1.1

- vApp contract + chat port (C is post-A but not v1.1-gated).
- Non-loop domain migrations.
- Multi-user / network daemon.
- Auto-updater.
- OTLP / metrics.
- Workstream identity + session-resume semantics (needs separate
  brainstorm; blocks CLI session-awareness).
- Shared object-model freeze (separate brainstorm; blocks CLI surface
  expansion).
