## §0 — TL;DR

EMA 0.0.6 has **good doctrine, good packages-as-spec, and a working daemon spine**, but the apps don't actually consume the spec layer. Three parallel implementations of the same event/IPC contract live across `apps/daemon` (hand-coded Gleam), `apps/web` (hand-defined TS), and `apps/cli` + `apps/agent-blueprint-grower` (each with its own ws-client). `packages/contracts-ts` and `packages/surface-core` are correctly designed but **not load-bearing** — apps don't import them.

The single highest-leverage architectural fix for 0.0.6 is to **make `packages/` load-bearing**: codegen the daemon's event types from `contracts/`, plumb `@ema/contracts-ts` into web/cli/grower, and consolidate IPC plumbing in `@ema/surface-core`. Everything else (IPC god module, web shell trim, dead Rust modules, place-tools legacy split) is downstream of, or a sibling to, that move.

Six core findings, eight rearchitecture moves, nine missions / ~17 lanes. New plan supersedes the morning's L0–L13 wave plan; ten of those lanes survive (renamed/reframed), four dissolve.

## §2 — The six core findings

### 2.1 Finding A — Packages are documentation, not infrastructure ⚠️ HIGHEST LEVERAGE
**Symptom:** Three parallel implementations of the same contract:
- `apps/daemon/src/ema_daemon/event_envelope.gleam` lines 94–225 — **126 event kinds** hand-coded.
- `packages/contracts/events/*.md` + `catalog.v0.md` — **144 event kinds** in canonical markdown.
- `packages/contracts-ts/src/generated/index.ts` — codegen of the markdown — **2,415 LOC of TS types not imported by anything**.
- `apps/web/src/lib/ipc.ts` — runs its own IPC client and projection-shape definitions.
- `apps/cli/src/ws-client.ts` — hand-rolled WS client, also reused via copy-paste in `apps/agent-blueprint-grower/src/emit.ts`.

**Impact:** 18-event drift between contracts (144) and daemon (126); web/CLI/grower drift independently; TS types are aspirational.

**Why it happened:** `packages/contracts-ts` codegen exists, but no app was migrated to consume it. `packages/surface-core/ipc-client` was scaffolded with reconnect/keepalive/timeout logic but the WS wiring was deferred ("pending daemon writer"). Each app rolled its own IPC plumbing in the meantime, and the meantime never ended.

**Fix posture:** Make packages load-bearing. Codegen Gleam types from `contracts/`, plumb `contracts-ts` into web/CLI/grower, finish surface-core IPC and migrate consumers. This is the single biggest 0.0.6 architectural lever.

### 2.2 Finding B — `ema_shell_ipc.gleam` is a 6,666-LOC god module
**Symptom:** All IPC routing — every command type, every subscription, every projection push — lives in one Gleam module. Imports 21 domain modules. Pattern matches over ~25+ command kinds inline.

**Impact:** Every new command requires editing the same file; bounded contexts (per `docs/architecture/05-writer-topology.md`) cannot evolve independently; module-level test/typecheck cycles are slow.

**Fix posture:** Split into per-domain routers (`ipc/hierarchy_router.gleam`, `ipc/blueprint_router.gleam`, `ipc/workspace_router.gleam`, `ipc/execution_router.gleam`, `ipc/content_router.gleam`, `ipc/time_router.gleam`, `ipc/replication_router.gleam`) plus a thin top-level `ipc/dispatch.gleam` (~200 LOC fan-out). Each router lives next to its domain modules.

### 2.3 Finding C — Bounded-context leakage (esp. orgs ↔ spaces, Elixir orphans)
**Symptom:** `ema_orgs.gleam` directly imports `ema_spaces` to seed the default space on org creation. Per `01-topology.md` "On org creation, the daemon should append `org.created` then `space.created`", but the writer-topology doctrine (`05-writer-topology.md`) says contexts communicate via events, not direct calls.

**Symptom (separate):** Elixir contexts `lib/ema_clients/`, `lib/ema_responsibilities/` (Slice 2) maintain ETS-backed projections WITHOUT subscribing to canonical bus events. They are architectural orphans — same process, separate truth lattice.

**Fix posture:**
- `ema_spaces` subscribes to `org.created` and emits `space.created` when policy says so.
- Elixir contexts subscribe to canonical events; ETS becomes a cache-only layer; emissions go through canonical commands.

### 2.4 Finding D — Web shell mixes 8 production vApps with 32 legacy place-tools
**Symptom:** `apps/web/src/components/apps/` has 48 vApp folders. 8 are EMA-canonical (atlas, blueprint, hq, cockpit, cwt, clients, agent-work, chronicle, …) and 32 are donor place.org tools (brain-dump, focus, tasks, habits, finder, music, …). They share the same registry, dock, theming, and component pool.

**Symptom (component bloat):** Top god components (>400 LOC) are mostly in legacy:
- `FinderApp.tsx` (1,404), `DesktopShortcuts.tsx` (1,059), `AmbientBar.tsx` (918), `CanvasCore.tsx` (877), `DayView.tsx` (788 focus + 704 rss), `BlueprintApp.tsx` (492).

**Symptom (design system not adopted in vApp interiors):** `var(--place-text-primary)` etc. hardcoded in inline styles inside vApps; theme tokens are applied at shell level but vApp interiors don't go through `@ema/design-system` JS mirrors.

**Fix posture:**
- Separate `apps/web/src/vapps/{ema,legacy}/` (per `FOLDER-AUDIT-2026-04-24.md` already-escalated lane `L-vapp-path-reconciliation`); gate legacy behind `?legacy=place` URL flag.
- Break up the 6 god components (FinderApp first; it's pure legacy and the largest).
- Land `eslint-no-restricted-syntax` rule against `var(--place-*)` in `apps/web/src/components/apps/ema/**`; require import from `@ema/design-system`.

### 2.5 Finding E — Dead and mirrored code
**Daemon:**
- `ema_replication`, `ema_peers`, `ema_collab_sync` — 347 LOC, **no replication loop in supervisor**.
- Several `*_ffi.erl` modules (`ema_device_keychain`, `ema_pairing_ffi`, `ema_collab_sqlite`, `ema_project_fs`) — unclear which are live vs PoC.

**Desktop:**
- `apps/desktop/src-tauri/src/{companion_protocol.rs, window_mgr.rs, ws_server.rs}` — **not invoked from `main.rs`**. Place-companion was supposed to land here (per L3) and didn't.

**Web:**
- Root `src/lib/ipc/` directory mirrors `src/lib/ipc.ts` (per inventory: "mirrored ipc/ structures (provider.tsx, use-command.ts, use-projection.ts in both root + ipc/ subdir — possible dead code"). Verify and delete one side.
- 38 generated `.js` twins beside `.ts/.tsx` (per `FOLDER-AUDIT-2026-04-24.md` line 20, escalated as `L-web-generated-source-twins`). Status unconfirmed for 0.0.6.

**Fix posture:** Cleanup commits, one cluster at a time, verify with grep + build.

### 2.6 Finding F — No schema migration spine
**Symptom:** `apps/daemon/canonical.db` schema is "assumed pre-initialized." No `_migrations/` directory, no version-aware schema apply on startup.

**Impact:** Once the daemon ships and users have local databases, every schema change becomes a hand-migration. Replication metadata, projection cache rebuilds, and event log invariants all rely on schema agreement.

**Fix posture:** Add `apps/daemon/_migrations/0001_init.sql` (current schema) + version table + apply-on-start. Versioning supports zero-downtime additive changes; destructive ones are flagged.

## §4 — Re-architecture proposal (8 moves)

The proposal is **load-path-first**: change what depends on what, not how things are written. Each move is independently shippable and creates a clean seam for future extension.

### Move 1 — Make `@ema/contracts-ts` load-bearing for TS apps
- Replace hand-defined event/command/projection types in `apps/web/src/lib/ipc.ts` with imports from `@ema/contracts-ts`.
- Replace hand-defined types in `apps/cli/src/commands/*.ts` with imports.
- Replace hand-defined types in `apps/agent-blueprint-grower/src/emit.ts` with imports.
- Add `pnpm check:contracts` gate that fails if any app re-defines a typed event/command shape (lint rule).

### Move 2 — Codegen Gleam from `contracts/`
- New package `packages/contracts-gleam/` with `codegen.ts` (or `.gleam`) parsing same `events/*.md`.
- Emits `apps/daemon/src/ema_daemon/contracts/events.gleam` with the 144-kind enum + payload types.
- Replaces `event_envelope.gleam` lines 94–225 (the hand-coded catalog) with generated equivalent. Handler dispatch remains in domain modules.
- Adds the daemon to the `check:contracts` gate.

### Move 3 — Finish `@ema/surface-core` IPC client; consolidate consumers
- Implement real WS in `surface-core/src/ipc-client/` (reuse logic from `apps/web/src/lib/ipc.ts` and `apps/cli/src/ws-client.ts`, plus existing reconnect/timeout/keepalive).
- Migrate `apps/web/src/lib/ipc.ts` → `import { IpcClient } from "@ema/surface-core"`.
- Migrate `apps/cli/src/ws-client.ts` → import.
- Migrate `apps/agent-blueprint-grower/src/emit.ts` → import.
- Result: one IPC client, one timeout policy, one reconnect strategy, one drift surface.

### Move 4 — Decompose `ema_shell_ipc.gleam`
- Carve into per-domain routers under `apps/daemon/src/ipc/`:
  - `ipc/hierarchy_router.gleam` (org / space / project / membership / invite / access_session / identity / device)
  - `ipc/blueprint_router.gleam` (document / section / gac / blocker / aspiration / decision / comment)
  - `ipc/workspace_router.gleam` (lane / queue / mission / campaign / handoff / problem / agent_report)
  - `ipc/execution_router.gleam` (dispatch / exec / tool)
  - `ipc/content_router.gleam` (collab / attachment / connector)
  - `ipc/time_router.gleam` (vcalendar / calendar_block / checkup)
  - `ipc/replication_router.gleam` (peer / lease / replication)
  - `ipc/dispatch.gleam` — top-level fan-out (~200 LOC), maintains the WS connection but delegates command decode/route to routers
- Each router has its own test file. Domain modules already exist (`ema_orgs/`, `ema_blueprint/`, …); routers just glue command-decode → domain-call → projection-push.

### Move 5 — Heal bounded-context leakage
- `ema_orgs.gleam` no longer imports `ema_spaces`. Org creation emits `org.created` only.
- `ema_spaces` adds an event subscription: on `org.created`, mint a same-named default space + emit `space.created`.
- Wire the Elixir contexts (`ema_clients`, `ema_responsibilities`) to subscribe to canonical events; their ETS becomes a fast read cache rebuilt from events on boot.

### Move 6 — Web shell hygiene (legacy split + god-component breakdown)
- Move 32 place-tools from `apps/web/src/components/apps/<tool>/` to `apps/web/src/vapps/legacy/<tool>/`.
- Production EMA vApps move to `apps/web/src/vapps/ema/<vapp>/` (per FOLDER-AUDIT-2026-04-24's escalated lane).
- Add URL flag `?legacy=place|ema|both` (default `ema` in production builds, `both` in dev).
- Break up the 6 god components — start with `FinderApp.tsx` (1,404 LOC, pure legacy, biggest single file).
- Delete mirrored `src/lib/ipc/` if it's a duplicate of `src/lib/ipc.ts`.
- Delete the 38 generated JS twins.

### Move 7 — Desktop place-companion: implement or remove dead modules
- Decide: are `companion_protocol.rs`, `window_mgr.rs`, `ws_server.rs` the foundation for place-companion (per L3), or scaffolding to delete?
- If foundation: wire them into `main.rs`, finish capabilities, expose Tauri commands (`companion.create_window`, `companion.move_window`, `companion.snap`, …) and document.
- If not: delete and document deferral.
- Either way: `apps/desktop/src-tauri/src/main.rs` should clearly own a working subset.

### Move 8 — Schema migration spine
- New `apps/daemon/_migrations/` with versioned `.sql` files (`0001_init.sql` from current schema).
- Daemon startup applies pending migrations, asserts version, refuses to boot on schema mismatch.
- Document in `docs/architecture/25-schema-migrations.md`.
