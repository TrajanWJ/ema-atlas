# EMA Native Knowledge Format

## Principle
EMA knowledge should not be one undifferentiated wiki blob.
It should preserve separate planes:
- canon
- planning / intention-building
- operational reality
- gap / reconciliation
- review / provenance / promotion receipts
- chronicle / historical record

## Native object categories
- intention
- proposal
- approval
- execution
- trace / step / observation
- workstream / session / thread
- artifact
- review
- memory
- machine
- service
- peer
- notification
- research item
- planning node
- note / meeting output / decision

## Native page/view structure
Every major object/view should support, where relevant:
- summary
- evidence
- timeline
- related objects
- freshness / last-validated
- open questions
- linked executions / workstreams
- review/promotion state

## Knowledge formatting rule
Do not flatten:
- aspiration
- implementation
- reality
- contradiction
- gap

into one fake “truth page.”
