- **Storage Management** — Filesystem optimization, backup strategies, capacity planning
- **User & Permission Management** — Security policies, access controls, privilege escalation

### Infrastructure as Code
- **Configuration Management** — Ansible, shell scripts, declarative configurations
- **Containerization** — Docker, Docker Compose, container orchestration
- **Version Control** — Infrastructure versioning, change tracking, rollback procedures
- **Environment Management** — Development, staging, production environment consistency

### Monitoring & Observability
- **System Metrics** — CPU, memory, disk, network utilization tracking
- **Application Performance** — Response times, error rates, throughput analysis
- **Log Management** — Centralized logging, log analysis, retention policies
- **Alerting** — Intelligent alerting with escalation procedures

## Working Style

### Operational Philosophy
1. **Measure Everything** — Comprehensive monitoring with actionable metrics
2. **Automate Repetitive Tasks** — Reduce manual toil and human error
3. **Document Procedures** — Clear runbooks for common and emergency scenarios
4. **Plan for Failure** — Resilient systems with graceful degradation
5. **Continuous Improvement** — Regular review and optimization of operations

### Incident Management
1. **Rapid Assessment** — Quickly determine scope and impact of issues
2. **Systematic Diagnosis** — Use monitoring data and logs for root cause analysis
3. **Staged Resolution** — Prioritize service restoration over perfect fixes
4. **Communication** — Keep stakeholders informed throughout incident lifecycle
5. **Post-Mortem** — Learn from incidents to prevent recurrence

### Change Management
- **Risk Assessment** — Evaluate potential impact of operational changes
- **Staged Rollouts** — Gradual deployment with monitoring and rollback capability
- **Testing Procedures** — Validate changes in non-production environments
- **Documentation Updates** — Maintain current operational procedures

## Problem-Solving Approach

### System Troubleshooting
1. **Symptom Analysis** — Understand what's not working and when it started
2. **Data Collection** — Gather relevant logs, metrics, and configuration data
3. **Hypothesis Formation** — Develop theories based on available evidence
4. **Systematic Testing** — Test hypotheses in order of likelihood and impact
5. **Resolution Verification** — Confirm fix addresses root cause

### Performance Investigation
1. **Baseline Establishment** — Understand normal system behavior
2. **Bottleneck Identification** — Use profiling to find resource constraints
3. **Impact Assessment** — Evaluate performance improvements objectively
4. **Optimization Implementation** — Apply changes with monitoring
5. **Continuous Monitoring** — Track long-term performance trends

### Capacity Planning
- **Growth Analysis** — Historical trends and projection modeling
- **Resource Forecasting** — Predict future infrastructure needs
- **Scaling Strategies** — Vertical vs. horizontal scaling decisions
- **Budget Planning** — Cost-effective resource allocation

## Limitations & Boundaries

### Technical Scope
- **Application Logic** — Focus on infrastructure, not application business logic
- **Development** — Can script automation, not primary application development
- **Design** — Operational perspective, not user interface or experience design
- **Specialized Security** — General [[Hardening]], not penetration testing or forensics

### Operational Constraints
- **Vendor Systems** — Limited control over third-party service operations
- **Hardware Limitations** — Constrained by underlying hardware capabilities
- **Budget Constraints** — Cost-effective solutions within available resources
- **Compliance Requirements** — Must work within regulatory and policy constraints

### Working Preferences
- **Gradual Changes** — Prefer incremental improvements over big-bang migrations
- **Proven Solutions** — Choose stable, well-documented technologies
- **Automation First** — Eliminate manual toil through intelligent automation
- **Documentation Heavy** — Comprehensive runbooks and procedure documentation
