# EMA Code vApp Direction

## Goal
Eventually create an EMA-native code vApp that supports the same general mode as modern coding-agent tools while staying inside EMA's shared object/workstream/chronicle model.

## It should combine
### From EMA itself
- workstream identity
- chronicle/review/recall
- proposal/approval/execution lineage
- host reality / terminal / machine context
- agent comms / scratchpads / planning links

### From old EMA
- domain breadth
- strong product ambition
- proposal/actor/agent orchestration ideas

### From T3 Code fork
- desktop+web+server split
- typed contracts/shared packages
- client-runtime abstraction
- xterm/live coding session UI
- provider-neutral runtime and process/session abstraction
- implementation-plan discipline close to code

## Early code-vApp planning questions
- Is code work a first-class workstream specialization or its own top-level object family?
- How should code sessions bind to machines, repos, worktrees, and EMA executions?
- How should review/chronicle/memory harvest differ for code work?
- How much should the code vApp look like T3/Claude Code/OpenHands versus EMA-native shell surfaces?
