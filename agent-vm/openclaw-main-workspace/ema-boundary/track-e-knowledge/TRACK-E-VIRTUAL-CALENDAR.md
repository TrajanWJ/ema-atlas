# Track E Virtual Calendar

## Why virtual calendar
Track E should include self-paced time as knowledge, not only fixed deadlines.

This calendar represents:
- phase sequence
- review cadence
- demo rhythm
- milestone checkpoints
- dependency pacing

It is intentionally resilient to drift.

## Cadence
- Weekly planning review
- End-of-sprint demo review
- Biweekly canon review
- Biweekly graph coverage / ontology review
- Monthly scope reset / backlog pruning

## Weeks 1–2
### Theme
Canon and ontology foundation
### Milestones
- canon model frozen enough for coding
- day-one concept registry agreed
- perspective registry drafted

## Weeks 3–4
### Theme
Storage, domain schema, and blueprint substrate
### Milestones
- DB schema and TS schema exist
- blueprint object and saved views work
- ephemeral canvas items defined

## Weeks 5–6
### Theme
Projection surfaces
### Milestones
- feed item model works
- wiki rendering works
- contradiction/freshness surfaces visible

## Weeks 7–8
### Theme
Research and cross-pollination
### Milestones
- source/artifact/claim import pipeline works
- suggestion engine works
- transfer suggestions visible

## Weeks 9–10
### Theme
Meta-EMA self-modeling
### Milestones
- core EMA docs ingested
- Track E plan represented inside graph
- gaps and contradictions represented

## Weeks 11–12
### Theme
Hardening and rollout
### Milestones
- operator scenarios pass
- parity/defer decisions for external donor patterns finalized
- v1 scope frozen

## Review prompts
### Weekly planning review
- what moved to canon?
- what remains provisional?
- what is blocked?
- what is stale?

### Canon review
- which objects should be promoted, superseded, or retracted?
- where are unresolved contradictions?
- where is authority scope unclear?

### Graph coverage review
- which EMA planes are under-modeled?
- which use cases from GitNexus / graphify remain uncovered?
- which operator questions still cannot be answered well?
