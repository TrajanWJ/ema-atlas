# Discord Server Architecture v3

**Date:** 2026-03-16
**Status:** Partially implemented — live items marked ✅, pending items marked ❌

---

## Design Philosophy

This server is a **living project management system**, not a chat server. Every channel exists because work flows through it. Every category maps to something real. Dead weight gets archived, not tolerated.

Core principles:
1. **Small active surface** — fewer channels, more forum threads
2. **Projects have lifecycles** — born as forum posts, promoted to categories, archived when done
3. **Vault is truth** — every project category maps to `vault/Projects/[name]/`
4. **Agents are invisible plumbing** — Right Hand is the voice, Orchestrator routes silently
5. **No branding theater** — no System, no lobster emoji, no corporate cosplay

### Category 3+: Promoted Projects (dynamic) ❌ NOT YET

When a project outgrows a single forum thread in `#projects`, it gets promoted to its own category. This is an explicit decision by Trajan, not automatic.

**Promotion criteria (any of these):**
- 3+ active forum threads about the same project
- Dedicated agent work spanning multiple sessions
- Multiple domains involved (code + research + ops)
- Trajan says "promote this"

**Promoted category template:**

```
📁 [Project Name]
├── #overview    (text)  — status, links, pinned context
├── #tasks       (forum) — work items, one thread per task
└── #research    (forum) — project-specific research (optional)
```

### Category: Archive ✅ LIVE

Bottom of the server. Where completed or abandoned work goes. Legacy channels (34) already here from v2 migration.

## Project Lifecycle ❌ NOT YET

Commands `/promote` and `/archive` not implemented. Lifecycle is manual.

```
1. IDEA          Trajan or an agent drops a forum post in #projects
                 Tags: 💡 idea

2. ACTIVE        Thread gets worked on. Tasks, code, research happen in-thread.
                 Tags: 🔨 active

3. PROMOTED      Project outgrows one thread → gets its own category.
                 (Manual — /promote not built yet)

4. COMPLETE      Work is done. Deliverables in vault.
                 (Manual — /archive not built yet)

5. ABANDONED     Project died. That's fine.
                 Tags: ❌ abandoned (with reason)
```
