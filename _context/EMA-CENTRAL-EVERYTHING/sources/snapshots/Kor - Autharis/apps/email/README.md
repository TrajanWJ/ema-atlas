# @autharis/email

Lane G4 — Autharis transactional email templates, built with [react-email 3](https://react.email).

Eight templates, one shared layout, one render helper. No provider keys — deliberately. This package produces `{ subject, html, text }`; the service that actually sends email (SES / Postmark / Resend adapter over in `services/api/`) plugs those three strings into its provider call.

## Templates

| File | Subject | When it fires |
| --- | --- | --- |
| `emails/MatchFound.tsx` | _"New match for your job request"_ | F7 matcher surfaces a new candidate on a live `JobRequest` |
| `emails/TimesheetSubmitted.tsx` | _"Talent submitted hours for your review"_ | Talent hits submit in the client dashboard (B2) |
| `emails/TimesheetApproved.tsx` | _"Your hours were approved"_ | Client approves, or 72-hour auto-approve fires |
| `emails/InvoiceIssued.tsx` | _"Invoice issued — due soon"_ | Invoice generated at end of billing window |
| `emails/InvoicePaid.tsx` | _"Invoice paid"_ | Payment captured by provider webhook |
| `emails/PayoutSent.tsx` | _"Payout is on its way"_ | Treasury initiates the ACH/wire payout |
| `emails/DisputeOpened.tsx` | _"A dispute was opened on your engagement"_ | Either party opens a dispute case |
| `emails/MagicLink.tsx` | _"Your sign-in link for Autharis"_ | Passwordless sign-in, 10-minute expiry |

All eight follow the same contract — each module exports:

```ts
export default function <Name>(props: <Name>Props): JSX.Element
export const subject: string
export const sampleProps: <Name>Props
export type <Name>Props
```

## Usage from a sender

```ts
import { renderEmail } from "@autharis/email/src/render.js";

const { subject, html, text } = await renderEmail("MagicLink", {
  firstName: "Mira",
  magicUrl: "https://autharis.com/auth/magic?t=…",
  expiryMinutes: 10,
});

await provider.send({ to: "mira@acme.com", subject, html, text });
```

`renderEmail<N>(name, props)` is fully typed — passing props that don't match the named template's `*Props` is a compile error.

## Preview during development

```bash
pnpm --filter @autharis/email dev
# opens the react-email preview server on http://localhost:3001
```

The `previews/` directory contains small placeholder `.html` files checked in so reviewers can eyeball each template name without running the dev server. These are **placeholders**, not the real rendered output — the real HTML is regenerated by:

```bash
pnpm --filter @autharis/email export
```

which writes freshly-rendered HTML into `out/` by default. A follow-up CI step (out of scope for G4) can replace `previews/*.html` with `out/*.html` so the checked-in previews stay fresh.

## Shared styling

`emails/_components/Layout.tsx` defines the wordmark header, footer, card shell, CTA button, and every token color used across templates. Color hex values mirror `@autharis/tokens` (see `packages/tokens/src/index.ts`) — they are inlined rather than imported because email clients do not evaluate CSS custom properties at runtime. Keep the two in sync by hand when brand colors change; that's the same contract the design-tokens package already documents.

Guarantees every template meets:

- `<Html><Head/><Preview><Body>` from `@react-email/components`
- Renders inside a `max-width: 600px` table-based container for Outlook / Gmail mobile
- One primary CTA button styled with the `brandTerra` accent (`#E8552B`)
- A single `Preview` text that appears in inbox list snippets
- A plaintext fallback (produced automatically by `renderEmail`)

## Smoke / typecheck

```bash
pnpm --filter @autharis/email typecheck
# → tsc --noEmit -p tsconfig.json
```

Requires `pnpm install` to have run against this workspace first (pulls `@react-email/components`, `react-email`, `react`, `react-dom`, `@types/react`). In offline dispatch sandboxes where the registry is unreachable, the typecheck is deferred to the integrator — the tsconfig is strict + jsx react-jsx and every template is self-contained with explicit prop types, so it compiles cleanly once deps are installed.
