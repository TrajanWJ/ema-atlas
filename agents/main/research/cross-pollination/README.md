# EMA Cross-Pollination System

Purpose: turn inspiration hunting into a durable operating system for EMA.

This folder is for:
- source registry
- builder watchlists
- steal/adapt/ignore decisions
- per-vApp inspiration maps
- concept harvests from promising but flawed repos
- tiny productivity and utility pollination, not just major control-plane surfaces

## Layout

- `registry/` — master source lists and ratings
- `builders/` — standout developers/orgs to watch
- `vapps/` — targeted pollination notes by vApp or product surface
- `imports/` — steal/adapt/ignore matrices and import candidates
- `notes/` — ad hoc observations and process lessons

## Current operating principles

- Favor signal over popularity.
- Favor weird but directly useful operator surfaces over generic AI hype.
- Preserve flawed-but-rich systems if they contain strong concepts.
- Rate sources by EMA-fit, not clout.
- Pollination applies to flagship surfaces and tiny productivity vApps alike.

## Process

1. Maintain a running registry of sources and builders.
2. Map sources onto concrete EMA vApps/surfaces.
3. Record what to steal, adapt, ignore, or revisit later.
4. Distill concepts into actionable product notes.
5. Keep user ratings and judgments alongside the sources.
