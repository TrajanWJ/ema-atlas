# v0.2 Core Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the three primary daily-use apps: Journal, Focus Timer, Terminal. Add Dashboard with basic metrics. Extend the SQLite schema for these features.

**Architecture:** Each app is a lazy-loaded component rendered inside the existing WindowManager. New SQLite tables added via migration v2. Apps use Zustand stores that wrap database queries. Focus Timer uses Document PiP, Screen Wake Lock, and Notification APIs.

**Tech Stack:** Existing stack + jquery.terminal (terminal), Canvas/SVG (focus timer ring)

**Spec:** `docs/superpowers/specs/2026-03-20-place-org-design.md` sections 5b-5e

Focus Timer features:
- SVG circular progress ring (stroke-dasharray animation)
- Time display: target time + actual elapsed
- Overrun indicator (ring changes color past target)
- Single "Transition" button: ends block, starts next (work→break→work)
- Optional label input
- Session stats: today's focus time, session count
- PiP: float mini timer over other tabs (Document PiP API with fallback)
- Wake Lock: screen stays on during active sessions
- Notifications: alert when target reached (Notification API)

Timer mechanics (from FlexiFocus spec):
- Timer uses timestamps, not intervals (accurate across backgrounding)
- Block records: target_ms, actual_ms, type (work/short_break/long_break)
- Default cycle: 25min work, 5min short break, every 4th break is 15min long break
- Timer NEVER stops — keeps counting past target. User decides when to transition.
