# CLI↔GUI Parity Contract (Draft)

## Core rule
If a human can do it in GUI, an agent should be able to do the equivalent through CLI.
If an agent does it in CLI, a human should be able to inspect/manage it in GUI.

## Shared parity expectations
- same IDs
- same lifecycle statuses
- same workstream identity
- same chronicle history
- same approvals/reviews
- same machine/session/notification linkage

## CLI-primary but GUI-visible
- scripted automation
- exact operational commands
- agent-native execution flows

## GUI-primary but CLI-reflectable
- spatial planning surfaces
- graph/timeline visualizations
- drag/drop composition
- rich review comparisons

## Non-negotiable mirrored domains
- intentions
- proposals
- approvals
- executions
- workstreams
- chronicle
- review
- memory links
- machines
- notifications
- scratchpads/comms references
