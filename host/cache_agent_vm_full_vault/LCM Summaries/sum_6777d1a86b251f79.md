## Build 1: Cost-Aware Agent Routing

**What:** The dispatch system should pick the cheapest effective agent for a task based on complexity.

Build `~/bin/dispatch-router.sh` that:
1. Reads a task JSON from stdin or as argument
2. Reads `agent-cards.json` from `~/.openclaw/agents/main/workspace/agent-cards.json`
3. Scores agents using:
   - **Capability match** — agent's `capabilities` array vs task's `agent` field or keywords in description
   - **Fitness** — higher fitness = more trusted
   - **Cost tier** — prefer lower cost when fitness is comparable (within 0.2)
   - **Runtime** — prefer faster agents for simple tasks (description < 100 chars)
4. Returns the recommended agent ID + reasoning as JSON: `{"agent": "ops", "score": 0.85, "reason": "best fitness for system tasks"}`
5. If task already specifies an agent, validate it's capable and return it (or warn if fitness < 0.3)

Also modify `~/bin/dispatch-engine.sh` — in the `dispatch_task()` function, if the task has no explicit `agent` field, call `dispatch-router.sh` to auto-assign one. Add a comment marking this as the cost-aware routing integration point.

## Build 2: Cross-Agent Memory Sharing via Vault

**What:** When agents discover useful knowledge during tasks, it should be stored in vault for other agents to find.

Build `~/bin/agent-vault-share.sh` that:
1. Scans `~/dispatch/done/` for completed tasks (last 24h)
2. For each task result file, extracts:
   - Key findings/learnings from the result text
   - Agent that produced it
   - Task type/domain
3. Creates vault notes at `~/vault/Agent Knowledge/<agent-name>/<date>-<topic>.md` with proper frontmatter:
   ```yaml
   ---
   title: "<topic from task>"
   created: <date>
   type: reference
   status: active
   confidence: 0.60
   source: agent:<agent-id>
   tags: [agent-knowledge, <agent>, <domain>]
   summary: "<one-line summary of finding>"
   ---
   ```
4. Links back to the task that produced it
5. Only creates notes for tasks with meaningful results (>100 chars, not just "DONE")
6. Deduplicates — checks if a vault note for this task already exists (by task_id in frontmatter)

**Since this does AI extraction of findings:** Use a simple heuristic — split result text into paragraphs, take paragraphs >50 chars that contain actionable words (built, created, found, discovered, implemented, fixed, error, issue, pattern). No LLM call needed.

Make both executable. Test dispatch-router.sh with a sample task. Test agent-vault-share.sh with existing done/ tasks.
