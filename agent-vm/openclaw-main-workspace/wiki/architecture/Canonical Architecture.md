# Canonical Architecture

## Summary
The canonical architecture is host-centered and evidence-first.

## Current truth
- EMA is the strongest existing candidate for the canonical runtime/control/session/context spine.
- Wiki Engine is the strongest candidate for canonical semantic memory.
- Claude and Codex have real host-native session stores.
- OpenClaw and ClaudeForge currently overlap as surfaces/bridges and must not become competing authorities.

## Canonical target
- EMA = canonical host control plane and context assembler
- Wiki = canonical semantic memory substrate
- Claude/Codex = host-native session providers
- OpenClaw/ClaudeForge = surfaces over EMA truth
- MCP = universal access layer generated from canonical contracts

## Transitional legacy notes

- provider-local/session-local/surface-local truths still overlap
- vault is still present but should no longer be primary operational memory

- incomplete Codex parity
- wiki-engine not yet fully normalized into EMA context packages
