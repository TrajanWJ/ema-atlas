# autharis-warehouse

Analytics pipeline — dbt + DuckDB. **Lane G7.** Python-adjacent, not a pnpm member.

Transforms seeded platform data (Talent, Jobs, Engagements, Timesheets, Invoices) plus a synthesized event stream (simulating the F8 WebSocket publish feed) into modeled marts:

- `mart_engagements` — engagement fact table joined with talent + job dimensions, with GMV.
- `mart_payouts` — invoice + timesheet roll-up per engagement, with platform fee + net payout.
- `mart_match_funnel` — job status funnel with conversion rate and avg days to first match.

The dev target writes a committable `warehouse.duckdb` file; production swaps the profile to Postgres.

---

## Quickstart

```bash
# 1. Install (Python >= 3.12)
pip install -e .
# or, minimal:
pip install "dbt-duckdb>=1.8" "duckdb>=1.0"

# 2. Regenerate the synthetic event stream (simulates F8 publish)
python3 scripts/export_events.py

# 3. Point dbt at the local profiles.yml
export DBT_PROFILES_DIR="$PWD"

# 4. Build
dbt seed
dbt run
dbt test
# or all three at once:
dbt build
```

`dbt build` produces `./warehouse.duckdb` containing the following schemas:

- `main_raw` — seed CSVs as raw tables.
- `main_staging` — typed, snake-cased staging views (`stg_*`).
- `main_marts` — materialized mart tables (`mart_*`).

## Docker

```bash
docker build -t autharis-warehouse .
docker run --rm -v "$PWD/out:/workspace/out" autharis-warehouse
```

The container runs `dbt build` on startup and produces `warehouse.duckdb` in the working directory. Mount a volume if you want the file surfaced to the host.

## Consumption notes

### G5 — status / uptime dashboard
`mart_match_funnel` (conversion rate + time-to-first-match) and `mart_payouts` (payout throughput) back the operational health panels on the status dashboard. Read via DuckDB query from `warehouse.duckdb`:

```python
import duckdb
con = duckdb.connect("services/warehouse/warehouse.duckdb", read_only=True)
con.sql("select status, job_count, conversion_rate from main_marts.mart_match_funnel").fetchall()
```

### E7 — analytics surface (Next.js)
`mart_engagements` (GMV), `mart_payouts` (platform fee + net payout), and `mart_match_funnel` (funnel + time-to-match) are the canonical sources for the E7 analytics dashboard. Preferred access paths:

1. **Export to Parquet** for E7 to load — `dbt run-operation` or a scheduled job writes `target/mart_*.parquet`.
2. **Direct DuckDB read-only** — E7's server loaders open `warehouse.duckdb` read-only. Not recommended for production but fine for dev.
3. **Postgres swap** — change the `dev` output in `profiles.yml` to `type: postgres` and E7's existing server layer (Lane E2) queries materialized marts via its own client.

Column contracts live in `models/marts/schema.yml` — not_null + unique tests enforce the grain for each mart.

### F8 — event stream
`scripts/export_events.py` synthesizes a CSV that mirrors the F8 Bun gateway's event union (`match-found`, `timesheet-submitted`, `invoice-paid`, `dispute-opened`, `message-received`). Swap the script for a small consumer that tails F8's `/ws` channel in production.

## Tests

- Column-level `not_null` + `unique` on every surrogate and natural key.
- `accepted_values` on `stg_talent.status`, `stg_jobs.status`, `stg_invoices.status`, `stg_events.event_type` to catch seed drift.
- Run via `dbt test` or as part of `dbt build`.
