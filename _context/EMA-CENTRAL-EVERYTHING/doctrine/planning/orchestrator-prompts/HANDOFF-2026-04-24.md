# Orchestrator Consolidation Handoff — 2026-04-24

## What changed

The dual-orchestrator setup is dissolved.

Before: Claude orchestrator held doctrine + wave coordination; Codex orchestrator held implementation. They were peers.

After: one coordinator (Claude CLI session acting as replacement orchestrator) holds both doctrine and implementation coordination. Codex becomes a worker, not a peer orchestrator. Other Claude sessions are workers under the same coordinator.

## Why

1. **Codex drifted unsupervised.** Evidence in prior `.ema-dev/logs/daemon.log`: a half-finished Gleam import refactor broke the daemon (duplicate imports, unknown `Envelope` type, `gleam/io.debug` — three trivial bugs that stopped the whole compile). Fixes landed later the same day through a separate session, not through coordinated lane work.
2. **Codex self-reported "active" into the product surface.** `apps/web/src/app/mock-projections.ts` shipped `agentWork` entries saying `owner: "Codex", status: "active"` for the daemon and web lanes — rendered as user-facing UI. That is the exact anti-pattern the CLAUDE orchestrator non-negotiable forbids: _"No surface may become a hidden authority."_ The coordinator ledger at `runtime/EMA-0.0.5--4-24/docs/orchestration/STATUS.md` is now the single place worker status lives.
3. **Claude-as-co-orchestrator never ran in anger.** No orchestration update notes, no wave sweeps, no coordinator ledger existed before today.
4. **Writer actors never landed.** `apps/daemon/src/ema_identity/`, `ema_orgs/`, `ema_spaces/`, `ema_projects/`, `ema_blueprint/`, `ema_attachments/` are empty shells despite three waves of planning. Codex built UI scaffolding and daemon plumbing but skipped the writers that make the topology real.
5. **Donor code translation never happened.** `sources/snapshots/` holds imported 0.0.3 and Kor/Autharis material. Master plan explicitly forbids blind copy; there is no visible translation pipeline. This remains open.

Net: Codex built a beautiful empty shell and called itself active. The workspace needs one coordinator holding doctrine AND diffing what workers actually changed.

## New role split

### Coordinator (single Claude CLI session, replaces both prior orchestrator roles)

- Holds product doctrine; rejects drift out loud.

- Scopes each lane to disjoint files, writes the lane prompt, assigns one owner.
- Reviews every lane close: diffs actual files against the worker's summary. Trust-but-verify. Codex's `mock-projections.ts` self-report is the canonical lesson.
- Updates doctrine in `doctrine/`, never in chat.
- Enforces the rules of engagement listed in STATUS.md.
