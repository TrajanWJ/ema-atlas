# EMA Mockup Revision Rubric

Use this when reviewing screenshots/mockups in Discord.

## 1. Identity clarity
- Does this clearly read as EMA?
- Does it feel like a control plane workbench, not generic PM software?
- Would a new viewer understand what EMA is trying to do?

## 2. Operational truth
- Is current state visible?
- Is trust/observed/inferred/verified state visible separately?
- Is attention/review state obvious?

## 3. Workstream clarity
- Can you tell what the authoritative lane is?
- Are tasks, sessions, and status coherently grouped?
- Does it feel like work has ownership and momentum?

## 4. Runtime clarity
- Do executions feel evidence-backed?
- Does the UI suggest cause/effect and recent activity?
- Is there enough density to feel useful?

## 5. Visual quality
- Is hierarchy strong?
- Is the spacing clean?
- Does it feel premium, dark, and calm?
- Does it look implementable?

## 6. Revision tags
Use short tags in review:
- `identity`
- `status`
- `trust`
- `workstream`
- `execution`
- `catalog`
- `density`
- `hierarchy`
- `polish`

Example:
- `workstream`: right panel is better, but lane ownership is still too vague
- `trust`: observed vs verified still not visually separated enough
- `identity`: this still feels like a generic ops dashboard, not EMA
