# EMA Graph Knowledge System

## Purpose
The Desktop deliverable should function as an EMA-native graph/wiki/ops codex with:
- two-way hyperlinks
- object pages
- plane-aware truth boundaries
- workstream-linked operational context
- chronicle/review provenance
- self-describing structure

## Core requirements
Every substantial document/object page should include:
- `Related:` links to sibling/parent/child pages
- `Backlinks expected from:` guidance where useful
- object type / plane / status metadata
- graph-relevant entities and edges

## Graph rule
The folder is not just a file tree. It is a graph encoded through:
- file placement
- explicit related-links sections
- repeated canonical object IDs/names
- plane-aware ownership
- index pages and object registries

## Desired capabilities
This deliverable should absorb and replace the useful parts of:
- Sugar-like project structuring
- explorer utilities
- Graphify-style relationship mapping
- GitNexus-style repo/context linking
- MemPalace-style memory/context organization
- superpowers / GSD-like execution support

without becoming another disconnected tool.
