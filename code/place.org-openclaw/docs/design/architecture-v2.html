Not a brand agency site (that's LetMeScale). This is a personal operating system floating in space — calm, focused, organic. Every pixel says "this person lives here."

2. Visual Design Language

Deep Space × Living Organism × Clean Cockpit

NOT LetMeScale (that's cinematic agency, dark reds, Bloomberg). place.org is a calm living space floating in deep blue-black. It breathes — colors shift with time of day, backgrounds gently move, light follows your cursor like bioluminescence. Clean and minimal, never cluttered.

Color Palette — Living

Base: deep blue-black (not pure black). Text: soft white (not harsh). Accent: living blue that shifts.

Time-of-Day Color Breathing

Background gradient shifts through the day. Dawn gets a warm rose hint. Midday is cleanest blue. Sunset goes purple. Night deepens. All shifts are slow — you don't notice them happening, you just feel the time of day.

Accent Color Shifts

  • Default: Cool blue #5b9cf5 — calm, focused
  • Focus mode active: Shifts warmer — subtle amber tint on borders and accents
  • Streak milestone: Brief green pulse on habit/streak elements
  • Overdue/urgent: Warm orange touches (never aggressive red unless critical)

Typography

  • Display: Variable font with weight range — clean geometric (e.g., Satoshi, General Sans, or custom)
  • Body: Inter / system-ui — crisp, readable at small sizes
  • Mono: JetBrains Mono / Geist Mono — terminal, data, code
  • Fluid scaling: clamp() for all sizes, 320px→1920px+
  • Letter spacing: Tight on headlines (-0.02em), open on small text
  • Weight: Light weights for large text (display), medium for body. Never heavy — the aesthetic is weightless, floating.

Surface Treatment

  • Windows: Frosted glass — backdrop-filter: blur(16px) + 1px border at rgba(100,160,255,0.08)
  • Cards: Nearly invisible elevation. Borders appear on hover like they're materializing.
  • Active elements: Soft blue glow on focus/hover — like bioluminescence, not neon.
  • Background: Slow-moving gradient mesh (CSS @property animating hue/position over minutes, not seconds).
  • Depth: z-layers with subtle parallax — background nebula, desktop, windows, modals, notifications.
  • Noise texture: Very subtle film grain overlay (CSS or SVG filter) — adds organic warmth to digital surfaces.

The "Living" System

The site is not static. It breathes.

  • Background mesh: 3-4 soft color blobs drift very slowly (CSS @property animation over 60-120 second cycles). Like a lava lamp in space at 0.1x speed.
  • Cursor light: Radial gradient follows pointer — like carrying a dim flashlight through deep water. Very low opacity. Reveals subtle texture on surfaces you hover near.
  • Time awareness: Background palette shifts with real time (see color bar above). Boot message references time of day.
  • Data-driven life: Ambient bar metrics aren't static text — they subtly pulse or shimmer when values change. Focus timer progress ring glows slightly brighter as you approach target.
  • Idle state: After 5 min idle, the desktop enters a "screensaver" — subtle particle drift or aurora effect. Any input wakes it.

Motion

  • Easing: cubic-bezier(0.65, 0.05, 0, 1) — fast start, smooth land. Feels natural.
  • Duration: 150ms micro-interactions, 300ms transitions, 600ms page changes
  • Spring physics: Motion library for dock hover, window open/close — bouncy but controlled
  • Scroll: Lenis smooth scroll on immersive pages, native on desktop
  • Principle: Motion communicates state change and hierarchy, never decorative. But ambient motion (background, cursor light) is always present — the site is alive even when you're not interacting.
  • Reduced motion: Respects prefers-reduced-motion. Ambient effects disabled. Functional transitions preserved but simplified.

5. Desktop App Windows — Full Detail

5a. 🧠 Brain Dump (GTD Inbox)

Philosophy: Capture EVERYTHING. Process LATER. The fastest path from thought to stored.

┌─────────────────────────────────────────────┐ │ 🧠 Brain Dump — □ ✕ │ ├─────────────────────────────────────────────┤ │ │ │ ┌─────────────────────────────────┐ 🎤 │ │ │ Type or speak... │ ⏎ │ │ └─────────────────────────────────┘ │ │ │ │ ─── Unprocessed (7) ────────────────── │ │ │ │ ┌─ 2 min ago ─────────────────────────┐ │ │ │ "Look into WebGPU compute shaders │ │ │ │ for data visualization" │ │ │ │ [Task] [Journal] [Archive] │ │ │ └─────────────────────────────────────┘ │ │ │ │ ┌─ 1 hour ago ───────────────────────┐ │ │ │ "Call dentist about Thursday" │ │ │ │ [Task] [Journal] [Archive] │ │ │ └─────────────────────────────────────┘ │ │ │ │ ┌─ Yesterday ────────────────────────┐ │ │ │ "LetMeScale needs new case study │ │ │ │ for the agency landing page" │ │ │ │ [Task] [Journal] [Archive] │ │ │ └─────────────────────────────────────┘ │ │ │ │ ─── Processed Today (12) ──── [show] ── │ │ │ │ [Process Mode] [Export] [Voice Mode] │ └─────────────────────────────────────────────┘
  • Capture: Single input. Type + Enter, or click mic for voice (Web Speech API). That's it. No categories, no tags, no friction.
  • Queue: Chronological list of unprocessed items. Relative timestamps.
  • Quick sort: Each item has action buttons — Task (creates task), Journal (moves to today's journal), Archive (saves but clears from inbox).
  • Process Mode: Full-screen card presentation. One item at a time. Decide and move on. GTD "clarify" step. Number keys for quick sort (1=Task, 2=Journal, 3=Archive, 4=Delete).
  • Voice Mode: Hands-free continuous capture. Speak, pause, speak again. Each pause creates a new item. Great for brain dumping while pacing.
  • Global shortcut: ⌘+↵ opens a floating mini-capture anywhere — type, Enter, it disappears. Doesn't even open the full window.
  • 2-minute rule: If an item takes less than 2 minutes, a subtle indicator suggests "just do it now."

  • Mirrors your vault daily template: ONE Thing focus, time blocks, notes, ideas, gratitude, reflection, metrics.
  • Markdown editor: Live preview with section sidebar navigation.
  • Calendar strip: Navigate between dates. Click any date to view/create entry.
  • Mood/Energy tracker: Physical (P), Mental (M), Emotional (E) on 1-10 scale. Visual indicators.

5c. ◉ Focus Timer (FlexiFocus Evolution)

Philosophy: Awareness, not enforcement. Soft boundaries. Your FlexiFocus spec, evolved with browser superpowers.

┌──────────────────────────────────────────────┐ │ ◉ Focus Timer — □ ✕ │ ├──────────────────────────────────────────────┤ │ │ │ ┌──────────┐ │ │ ╭────│ 25:00 │────╮ │ │ ╱ │ target │ ╲ │ │ │ │ │ │ ← circular │ │ │ │ 32:47 │ │ progress │ │ ╲ │ actual │ ╱ ring │ │ ╰────│ │────╯ │ │ └──────────┘ │ │ │ │ ┌── OVERRUN: +7:47 ──┐ │ │ │ You passed your │ │ │ │ target. Keep going │ │ │ │ or transition. │ │ │ └────────────────────┘ │ │ │ │ ┌────────────────────────┐ │ │ │ ⏭ TRANSITION │ ← single │ │ └────────────────────────┘ button │ │ │ │ Label: [FlexiFocus PiP ▾] [+ tag] │ │ │ │ Session: W1 → B1 → W2 → B2 → W3 → ... │ │ Today: 2h 14m focused │ 3 sessions │ │ │ │ [🔊 Ambient] [📌 PiP] [📊 Analytics] │ └──────────────────────────────────────────────┘
  • Core mechanic: Timer notifies at target. Never stops. User decides when to transition. Overrun is first-class data.
  • Single Transition button: Ends current block, logs it, starts next (work→break→work). Minimal interaction.
  • Circular progress ring: SVG/Canvas. Fills to 100% at target, then changes color and keeps going (overrun visualization).
  • Labels: Optional. Add during or after. Reclassify blocks after the fact.
  • Picture-in-Picture: Document PiP API — float a mini timer over other browser tabs. Shows time + transition button.
  • Screen Wake Lock: Screen Wake Lock API — screen stays on during focus sessions.
  • Ambient sound: Built-in soundscapes (rain, lo-fi, white noise). Web Audio API with AnalyserNode for waveform.
  • Notifications: Notification API — "Target reached!" even when tab is backgrounded.
  • Analytics panel: Charts (daily/weekly focus hours, overrun patterns, work/break ratios). From SQLite aggregation.
  • Journal integration: On session end, prompt: "What did you focus on?" → auto-creates journal note.
  • Session model: Identical to FlexiFocus spec — blocks with target_ms, actual_ms, type, label, overrun.

5d. ✓ Tasks

Philosophy: Must/Should/Could priority matrix. Linked to goals. Not a Jira clone — a personal task surface.

  • Priority levels: Must-do (red), Should-do (orange), Could-do (blue), Won't-do (archived)
  • Categories: Work, Personal, Learning/Growth, Health/Wellness (from your daily template)
  • Quick add: Type + Enter at top. Assign priority with keyboard shortcut.
  • Due dates: Optional. Overdue items surface in ambient bar and Brain Dump.
  • Goal linking: Tasks can link to goals from the Dashboard. "This task advances: [Ship Focus Timer]".
  • Drag to reorder. Drag between priority groups. Drag to calendar for time-blocking.
  • Incomplete processing: At end of day/week, unfinished tasks prompt "Why? → Reschedule / Delegate / Delete" (from your weekly review template).
  • Views: List (default), Kanban (by status), Calendar (by due date).

5e. 📊 Dashboard

Philosophy: Your goal cascade at a glance. THE ONE THING front and center. Energy as a metric.

  • The ONE Thing: Largest element. "What's the ONE thing such that by doing it, everything else becomes easier?" Editable daily.
  • Goal cascade: Collapsible tree — 3-Year Vision → Yearly Goals → Monthly Goals → This Week. Each with progress %.
  • Energy gauge: Physical / Mental / Emotional (1-10). Visual meter. Set once per day, tracked over time.
  • Daily metrics panel: Deep work hours, tasks completed, inbox zero status, focus sessions.
  • Weekly trend: Sparkline charts for focus time, task completion, energy levels over the past 7 days.
  • Active projects: List of current projects with status indicators and last-touched date.

5f. 🔄 Review

Philosophy: GTD weekly review digitized. Collect → Reflect → Plan. Three phases, guided.

  • Phase 1 — Collect: Surface all unprocessed brain dumps, incomplete tasks, unreviewed journal entries. "Is everything captured?"
  • Phase 2 — Reflect: Wins, challenges, lessons learned. Incomplete task processing (why didn't this get done?). Energy trends.
  • Phase 3 — Plan: Set next week's ONE Thing. Fill priority matrix. Plan day-by-day time blocks. Set habit targets.
  • Monthly mode: Same flow but zoomed out — monthly goal progress, project status updates, quarterly check-in.
  • Guided wizard: Step-by-step cards walk through each phase. Not a blank page — structured prompts.
  • Export: Generate markdown weekly review note compatible with Obsidian vault template.

5g. 📅 Calendar

  • Views: Day (time blocks), Week (overview), Month (summary).
  • Time blocks: Visual blocks from journal's time block section. Drag to adjust.
  • Focus sessions: Auto-populated from Focus Timer data. Shows actual vs planned.
  • Events: Manual creation. Reminders via Notification API.
  • Drag from Tasks: Drag a task to a time slot to schedule it.
  • Today indicator: Current time marker that scrolls with real time.

5h. 🔥 Habits

  • Active limit: 5-7 habits max. System enforces this — must archive one to add another.
  • Daily habits: Morning routine, exercise, reading, etc. Checkbox per day.
  • Weekly habits: Exercise 3x, deep work 5x, learning 3hrs — with target and actual.
  • Streak visualization: GitHub-style contribution grid. Longest streak highlighted.
  • Habit heat map: Which days of the week are strongest? Time-of-day patterns?
  • Integration: Some habits auto-track — "Deep work 5x" counts from Focus Timer sessions.
  • Gentle reminders: Notification at configurable times if habit not checked.

-- ===================== BRAIN DUMP / INBOX =====================
CREATE TABLE inbox (
  id          TEXT PRIMARY KEY,
  content     TEXT NOT NULL,
  source      TEXT DEFAULT 'text',  -- 'text' | 'voice'
  processed   INTEGER DEFAULT 0,
  action      TEXT,                  -- 'task' | 'journal' | 'archive' | NULL
  created_at  TEXT NOT NULL,
  processed_at TEXT
);

-- ===================== JOURNAL =====================
CREATE TABLE journal_entries (
  id          TEXT PRIMARY KEY,
  date        TEXT NOT NULL UNIQUE,  -- YYYY-MM-DD, one per day
  content     TEXT NOT NULL,          -- full markdown
  one_thing   TEXT,                   -- today's ONE focus
  mood        INTEGER CHECK(mood BETWEEN 1 AND 10),
  energy_p    INTEGER CHECK(energy_p BETWEEN 1 AND 10),  -- physical
  energy_m    INTEGER CHECK(energy_m BETWEEN 1 AND 10),  -- mental
  energy_e    INTEGER CHECK(energy_e BETWEEN 1 AND 10),  -- emotional
  gratitude   TEXT,                   -- JSON array of 3 strings
  tags        TEXT,                   -- JSON array
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE VIRTUAL TABLE journal_fts USING fts5(content, one_thing, tags, content=journal_entries);

-- ===================== FOCUS SESSIONS =====================
CREATE TABLE focus_sessions (
  id          TEXT PRIMARY KEY,
  started_at  TEXT NOT NULL,
  ended_at    TEXT,
  status      TEXT DEFAULT 'active'  -- 'active' | 'completed' | 'abandoned'
);
CREATE TABLE focus_blocks (
  id          TEXT PRIMARY KEY,
  session_id  TEXT NOT NULL REFERENCES focus_sessions(id),
  type        TEXT NOT NULL,          -- 'work' | 'short_break' | 'long_break'
  target_ms   INTEGER NOT NULL,
  actual_ms   INTEGER,
  overrun_ms  INTEGER GENERATED ALWAYS AS (actual_ms - target_ms) STORED,
  label       TEXT,
  tags        TEXT,                   -- JSON array
  started_at  TEXT NOT NULL,
  ended_at    TEXT
);

-- ===================== TASKS =====================
CREATE TABLE tasks (
  id          TEXT PRIMARY KEY,
  title       TEXT NOT NULL,
  description TEXT,
  priority    TEXT DEFAULT 'should',  -- 'must' | 'should' | 'could'
  category    TEXT,                    -- 'work' | 'personal' | 'learning' | 'health'
  status      TEXT DEFAULT 'pending', -- 'pending' | 'in_progress' | 'done' | 'archived'
  due_date    TEXT,                    -- YYYY-MM-DD
  goal_id     TEXT REFERENCES goals(id),
  sort_order  INTEGER DEFAULT 0,
  created_at  TEXT NOT NULL,
  completed_at TEXT,
  incomplete_reason TEXT              -- "Why didn't this get done?"
);

-- ===================== GOALS =====================
CREATE TABLE goals (
  id          TEXT PRIMARY KEY,
  title       TEXT NOT NULL,

  parent_id   TEXT REFERENCES goals(id),  -- cascade hierarchy

  status      TEXT DEFAULT 'active',
  target_date TEXT,

  updated_at  TEXT NOT NULL

  id          TEXT PRIMARY KEY,

11. Mobile Strategy

Rule: No draggable windows on mobile. The desktop becomes a launcher. Everything else adapts.

Desktop → Launcher

  • Ambient bar becomes compact header (date, one metric)
  • Apps shown as vertical card list (swipe between)
  • Tap card → app fills screen
  • Swipe right → back to launcher
  • Bottom nav: Brain Dump, Journal, Focus, Tasks, More
  • Quick capture: floating ⌘+↵ button always visible

Immersive Pages

  • Work naturally — scroll experiences are mobile-native
  • 3D hero → simplified 2D animation on mobile
  • Horizontal scroll → vertical stack or swipeable
  • Touch-optimized: 44px min touch targets
  • Same View Transitions between launcher and pages
