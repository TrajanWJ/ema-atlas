# Wholesaling AI Workspace Doctrine

## Core idea
This workspace should not be organized like a generic Discord server or a random pile of agent channels.

It should be organized like a domain-specific operational IDE for wholesaling AI.

That means the structure must support:
- many active workstreams at once
- agents operating in parallel
- command and routing clarity
- domain separation between houses and land
- shared AI/orchestration layers
- visible verification and completion loops

---

## What problem this solves
Traditional Discord layouts break down when they try to hold:
- chat
- project management
- agent execution
- logs
- archives
- multiple domains
- multiple owners

in one flat or chaotic structure.

The result is noise, duplicated channels, unclear ownership, and constant context switching.

The fix is not more channels.
The fix is a better environment model.

---

## Environment model
The workspace should behave like a larger operational environment with three layers:

### 1. Human command layer
Purpose:
- decisions
- priorities
- routing
- queue management
- blockers
- done feed

This layer should stay small and high-signal.

### 2. Domain execution layer
Purpose:
- active workflows
- agent collaboration
- operational subdomains
- pipeline-specific reasoning and outputs

For Adil, this means:
- Wholesaling AI
- Wholesaling Houses
- Wholesaling Land

### 3. Shared systems layer
Purpose:
- orchestration
- infrastructure
- automations
- verification
- shared tools
- cross-workspace support

This layer is for systems that affect both Adil and Trajan.

---

## Ownership model
### Adil owns
- wholesaling AI
- wholesaling houses

### Trajan owns
- Trajan-specific project lanes

### Shared AI Workspace owns
- shared orchestration

## Domain doctrine
Adil’s domain should split cleanly into:

### A. Wholesaling AI
The intelligence and automation layer.

Examples:
- agent design
- routing systems
- enrichment systems
- follow-up automation
- KPI intelligence
- AI architecture

### B. Wholesaling Houses
The house wholesale execution layer.

Examples:
- house intake
- list building
- distress stacking
- seller motivation scoring
- outreach
- seller-response triage
- fast underwriting
- buyer match / dispo

### C. Wholesaling Land
The land wholesale execution layer.

Examples:
- land intake
- buyer criteria
- land sourcing
- zoning and entitlement
- parcel constraints
- seller qualification
- underwriting
- buyer match / dispo

These three lanes should be distinct but coordinated.

---

## Channel survival test
A live channel should only exist if it has:
- a clear owner
- a clear purpose
- clear inputs
- clear outputs
- real active usage
- low overlap with other channels

If not, it should be archived, merged, or never created.

---

## Queue doctrine
The queue is one of the highest-value surfaces.

Every queue item should be:
- concrete
- assignable
- scoped
- outcome-oriented
- visible

Bad queue item:
- improve workflow

Good queue item:
- define house seller triage schema with hot/warm/nurture/dead routing and next-step outputs

---

## Signal doctrine
High-signal surfaces should answer one of these questions:
- what needs to be done?
- what is active right now?
- what is blocked?
- what was completed?
- what system owns this?
- what should happen next?

If a channel does not help answer those, it is probably clutter.

---

## Legacy doctrine
Legacy material is reference, not command.

Old categories and stale lanes should be clearly marked as legacy and visually downgraded so they do not compete with the live surface.

The rule is:
- preserve useful context
- migrate only high-signal value
- archive the rest

Do not endlessly rehabilitate clutter.

---

## Design principle
Do not build a normal Discord server.
Build a domain-specific, multi-agent operational environment for wholesaling AI.

That is the correct frame.
