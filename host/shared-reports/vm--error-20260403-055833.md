## PART 2: CLI Manager System (The "ClaudeForge" of EMA)

A unified manager for ALL coding CLI tools. This is the backbone.

### Backend: daemon/lib/ema/cli_manager/

1. **CliManager context** (daemon/lib/ema/cli_manager/cli_manager.ex):
   - Registry of known CLIs (Claude Code, Codex, Aider, OpenCode, etc.)
   - Each CLI has: name, binary_path, version, capabilities, config_path, session_dir
   - Auto-detect installed CLIs by scanning PATH and common locations
   - Store in SQLite: `cli_tools` table

2. **CliSession schema** (daemon/lib/ema/cli_manager/session.ex):
   - id, cli_tool_id, project_path, status (running/idle/crashed/completed), pid, started_at, ended_at
   - linked_task_id (optional — from proposals)
   - linked_proposal_id (optional)
   - output_log_path, exit_code
   - cost_estimate (if available from the CLI)

3. **SessionRunner GenServer** (daemon/lib/ema/cli_manager/session_runner.ex):
   - Start a CLI session: spawn process, capture stdout/stderr via Port
   - Monitor process health (alive/crashed)
   - Send commands to running sessions
   - Kill/stop sessions
   - Auto-create CliSession records

4. **CliScanner** (daemon/lib/ema/cli_manager/scanner.ex):
   - Scan the system for installed CLIs
   - Check `~/.claude/`, `~/.codex/`, `~/.aider/`, `~/.opencode/` for configs
   - Read Claude Code session history from `~/.claude/projects/` JSONL files
   - Read Codex sessions from `~/.codex/`
   - Return unified view of all sessions across all CLIs

5. **REST endpoints:**
   - GET /api/cli-manager/tools — list registered CLIs
   - POST /api/cli-manager/tools — register a new CLI
   - GET /api/cli-manager/sessions — list all sessions (across all CLIs)
   - POST /api/cli-manager/sessions — start a new session (pick CLI + project + prompt)
   - GET /api/cli-manager/sessions/:id — session detail with output
   - POST /api/cli-manager/sessions/:id/stop — stop a session
   - DELETE /api/cli-manager/sessions/:id — kill a session
   - POST /api/cli-manager/scan — trigger auto-detection scan

6. **Migrations:**
   - create_cli_tools: id, name, binary_path, version, capabilities (json), config_path, session_dir, detected_at
   - create_cli_sessions: id, cli_tool_id, project_path, status, pid, prompt, started_at, ended_at, linked_task_id, linked_proposal_id, output_summary, exit_code, cost_estimate

### Frontend: app/src/components/cli-manager/

1. **CliManagerApp.tsx** — full app with tabs: Sessions | Tools | History
2. **SessionCard.tsx** — individual session with status, runtime, actions
3. **NewSessionModal.tsx** — pick CLI tool, pick project, write prompt, optionally link to task/proposal
4. **CliToolCard.tsx** — registered CLI with version, path, session count
5. **cli-manager-store.ts** — Zustand store with REST + WebSocket
