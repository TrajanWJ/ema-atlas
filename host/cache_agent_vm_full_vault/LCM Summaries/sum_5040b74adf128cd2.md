## 1. Intent Classifiers in Agent Frameworks

### 1.1 AutoGen (Microsoft) — SelectorGroupChat

**Architecture:** LLM-as-router. A "selector" model reads the full conversation context plus agent `name` and `description` fields, then picks the next speaker.

**Metadata extracted:** Conversation history, agent names/descriptions, prior speaker identity.

**Routing decision:** The selector LLM generates a single agent name. Optional `candidate_function` narrows the pool before the LLM chooses. Optional `selector_function` can override the LLM entirely with deterministic logic.

**Prompt enhancement:** None built-in. The planning agent pattern (demonstrated in docs) shows a PlanningAgent that decomposes tasks into subtasks and assigns them, but this is user-implemented, not framework-level.

**Strengths:** Flexible — LLM-based selection adapts to novel intents. Customizable via selector/candidate functions. Supports `allow_repeated_speaker` control.
**Weaknesses:** No dedicated intent extraction step. No prompt rewriting before dispatch. Selection prompt is generic — no structured metadata (intent, complexity, domain). Relies entirely on agent descriptions being well-written.

**Source:** [T1] microsoft.github.io/autogen/stable — SelectorGroupChat docs

### 1.2 CrewAI — Hierarchical Process

**Architecture:** Two modes: `sequential` (fixed pipeline) and `hierarchical` (manager-routed). In hierarchical mode, a `manager_agent` (or auto-created manager using `manager_llm`) coordinates task assignment.

**Metadata extracted:** Task descriptions, agent role/backstory/goal, tool availability, crew-level knowledge sources.

**Routing decision:** The manager LLM assigns tasks to agents based on their roles. Optional `planning` mode: before execution, an AgentPlanner generates a plan that gets injected into each task description.

**Prompt enhancement:** The `planning` feature is the closest to prompt enhancement — it rewrites task descriptions with plan context. Custom `prompt_file` allows overriding the internal prompts used for coordination.

**Strengths:** Planning-before-execution is a real pre-dispatch enrichment step. Role/backstory/goal gives rich agent metadata. Memory system (short-term, long-term, entity) provides context accumulation.
**Weaknesses:** Planning is coarse-grained (crew-level, not per-message). No intent classification taxonomy. Manager routing is opaque — no structured routing metadata exposed.

**Source:** [T1] docs.crewai.com/concepts/crews

### 1.3 LangGraph — Supervisor & Handoff Patterns

**Architecture:** Graph-based. Two primary multi-agent patterns:
1. **Supervisor:** A central node (LLM) routes to worker nodes via tool-calling. The supervisor has tools like `transfer_to_researcher`, `transfer_to_coder`.
2. **Swarm/Handoff:** Agents hand off to each other directly via tool calls (inspired by OpenAI Swarm).

**Metadata extracted:** State object (arbitrary dict), message history, tool schemas.

**Routing decision:** Supervisor pattern: LLM decides routing via structured tool calls. Handoff pattern: active agent decides to transfer. Both leverage the LLM's function-calling capability.

**Prompt enhancement:** Not built-in. The graph structure allows inserting transformation nodes between supervisor and workers, but this is user-implemented.

**Strengths:** Maximum flexibility — arbitrary graph topology. State management is first-class. Can implement any routing pattern (conditional edges, parallel fan-out, cycles). Checkpointing and human-in-the-loop built in.
**Weaknesses:** Low-level — you build everything yourself. No opinionated intent classification. No built-in prompt enrichment. Steep learning curve.

**Source:** [T1] LangGraph docs (redirected; based on published concepts documentation)
