# EMA Visual System

## Product mood
- dark, quiet, focused
- precision over decoration
- subtle color, sharp hierarchy
- premium but not glossy
- command center, not consumer toy

---

## Visual references to steal from
- Linear: decisive spacing, chips, filters
- Plane: clean work-item ergonomics
- Airflow/Temporal: analytical layouts
- Argo CD: decomposed status blocks
- Backstage: entity-first thinking
- Leantime: work + schedule coexistence

---

## Core layout rules

### 1. Persistent chrome
- top nav always present
- left spine for lane/entity navigation
- page-local controls under page header

### 2. Two dominant page patterns
- **board/list workspace**
- **detail + status rail**

### 3. Information density
- compact but breathable
- prefer grouped sections over giant blank surfaces
- use cards as structural containers, not decoration

---

## Color semantics
- primary = focus / selected / active navigation
- success = healthy / running / verified
- warning = review / stale / at risk
- error = broken / failed / blocked
- info = observed / runtime / live signal
- muted = inferred / background / archived

Never mix lifecycle and trust without labeling them separately.

---

## Typography hierarchy
- page title: strong, calm, not oversized
- eyebrow labels: tiny uppercase, high tracking
- chips/badges: compressed and decisive
- metadata: mono or semi-mono where useful

---

## Card anatomy
Every important card should ideally support:
- title
- short explanation
- status chips
- trust badge
- one line of metadata
- actionable count or next signal

---

## Status language
Always separate:
- health/status
- trust/observed state
- review/attention state
- activity recency

---

## Mockup quality bar
High-quality mockups should feel:
- implementable
- structurally coherent
- crisp in spacing and hierarchy
- specific to EMA, not generic SaaS filler
- rich with believable operator data
