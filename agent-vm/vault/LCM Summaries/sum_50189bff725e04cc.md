## Server Structure

```
📂 CLAUDE REMOTE — HOST
├── #command-center     ← session management, spawn/kill, status dashboard
├── #task-queue         ← dispatch board, priority queue, active work
├── ─────────────────
├── 📁 ~/Desktop/Coding/project-a    ← category = path on host
│   ├── #main           ← Claude Code session (thread-bound ACP)
│   └── #refactor-auth  ← another session, same project
├── 📁 ~/Desktop/Coding/project-b
│   ├── #main
│   └── #fix-build
├── 📁 ~/Documents/vault
│   └── #reorganize
└── 📁 /etc/nginx
    └── #config-audit
```

## How It Works

**Opening a location:** You type `/open ~/Desktop/Coding/myapp` in #command-center → bot creates a category named after the path, spawns a #main channel, starts a Claude Code ACP session bound to that directory.

**New sessions:** `/session fix-types` inside any category → creates a new channel, spawns a Claude Code session at that category's path with the task context.

**Every channel message** goes to the bound Claude Code session via `sessions_spawn(runtime: "acp", thread: true)`. Responses come back to the channel. Full capabilities — file edits, terminal, MCP servers, everything.

**1:1 sync:** Each channel maps to a real Claude Code session on the host. The session ID is pinned in the channel topic. You could pick up the same session from the host terminal or web UI using the session ID.

## Implementation Layers

1. **Discord bot logic** (OpenClaw plugin or skill) — handles `/open`, `/session`, `/close`, category/channel CRUD
2. **Session registry** — JSON mapping `{channelId → {path, sessionId, status}}` — persisted to disk
3. **ACP bridge** — each channel routes messages to its bound `sessions_spawn(runtime: "acp")` session
4. **Cleanup** — `/close` archives the category, kills the session. Idle timeout optional.
5. **Web mirror** — Canvas or a lightweight web UI showing the same session tree + live output
