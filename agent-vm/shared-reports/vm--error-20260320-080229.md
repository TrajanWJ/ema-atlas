**Prompt:** Fix a critical bug in the ClaudeProvider (packages/server/src/providers/claude-provider.ts).

## The Bug
`startSession()` spawns `claude --print --output-format stream-json` with NO stdin and NO prompt argument. Claude CLI errors: 'Input must be provided either through stdin or as a prompt argument when using --print'. This means:
1. The initial session always fails silently
2. `providerSessionId` is never captured from the result event
3. `sendMessage()` then tries `--resume undefined` which also fails

## The Fix
Make `startSession()` **lazy** — don't spawn Claude. Just:
1. Create the tmux session (keep this, useful for debugging)
2. Yield `session_init` with a placeholder ID
3. Yield `done` immediately
4. Store session metadata but mark it as 'not yet started'

Then in `sendMessage()`:
- If session has NO `providerSessionId` (first message), spawn `claude --print --output-format stream-json --permission-mode bypassPermissions` with the message piped to stdin. Capture the session_id from the result event.
- If session HAS a `providerSessionId` (subsequent messages), use `--resume <id>` as it does now, pipe message to stdin.

## Key constraints
- Keep tmux session creation in startSession (useful for manual attach)
- Keep the edit-in-place streaming pattern in mapEvent
- The session_id is in the `result` event JSON: `event.session_id`
- Don't change the sendMessage signature or any other files
- Keep all existing mapEvent logic

Test the fix works by checking the tmux pane output isn't an error.
