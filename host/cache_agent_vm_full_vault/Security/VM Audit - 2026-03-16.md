### ⚠️ Finding: Docker Bypasses UFW (Medium Severity)

Docker modifies iptables directly, so ports published with `-p` are network-accessible regardless of UFW rules. The [[Laminar]] stack (ports 5433, 5667, 7280-7281, 8000-8002, 8903) is reachable from the host network.

**Risk:** Low in practice — this VM sits on a private KVM bridge (192.168.122.0/24) with only the host as a neighbor. No internet exposure.

**Recommended action (if desired):**
- Bind Docker ports to localhost: change `-p 8000:8000` to `-p 127.0.0.1:8000:8000` in Docker Compose
- Or set `DOCKER_OPTS="--iptables=false"` and manage iptables manually
- Or accept current posture since it's a private network

### ⚠️ Finding: PasswordAuthentication Not Explicitly Disabled (Low Severity)

The default is `yes`, meaning password-based SSH login is allowed. Since UFW restricts SSH to 192.168.122.1 only, the blast radius is minimal.

**Recommended action:** Add `PasswordAuthentication no` to `/etc/ssh/sshd_config` for defense-in-depth.
